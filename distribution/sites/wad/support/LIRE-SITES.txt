CONFIGURATION DES SITES — GLPI-Pilot 3.4.0

INSTALLATION
1. Fermer complètement GLPI-Pilot, y compris une ancienne version ouverte.
2. Extraire ce ZIP dans le dossier qui contient GLPI-Pilot.exe.
   Fusionner le dossier wad du ZIP avec le dossier wad existant.
3. Vérifier la présence de wad\sites.csv à côté des autres fichiers.
4. Ouvrir GLPI-Pilot.exe. L’import se fait automatiquement au démarrage.
5. Ouvrir Terrain → Gérer le référentiel, puis choisir Type : Site.
   Le type Ville permet de vérifier les communes.
6. Dans Données → Importer CSV / Excel, importer votre extrait d’incidents,
   puis ouvrir Terrain pour essayer le référentiel dans la simulation.

Le lanceur facultatif wad\support\INSTALL-SITES.cmd ouvre le même EXE.
Ce complément ne contient pas GLPI-Pilot.exe ; extraire le logiciel d’abord.
Le CSV est inchangé depuis l’édition géographique 3.3.3 et reste compatible
avec GLPI-Pilot 3.3.3 ou ultérieur. Cette notice décrit les chemins 3.4.0.

PROFIL UTILISATEUR
Les données sont enregistrées dans :
%LOCALAPPDATA%\GLPI-Pilot\settings.json
Rubriques Cities.Sites et Cities.Cities, modifiables depuis
Terrain → Gérer le référentiel.
Une sauvegarde complète précède la modification des réglages.

Un profil neuf reçoit les sites, les termes et leur géographie.
Un profil déjà initialisé reçoit seulement les informations géographiques
manquantes des sites et communes toujours présents. Les valeurs locales,
identifiants et rattachements personnalisés sont conservés. Les sites
supprimés ou renommés ne sont pas recréés, les alias retirés restent retirés.
Un fichier identique n’est pas réappliqué. Son absence ne bloque pas l’EXE.

SIMULATION
Fermer complètement le logiciel après placement du fichier, puis relancer.
Un nouvel import CSV d’incidents reprend les réglages du profil dans une
simulation isolée. Les modifications d’essai ne changent pas ce profil.
La démonstration sans fichier utilise ses propres références fictives.
Quitter la simulation restaure le profil et le relevé habituels.

TERRAIN : SITES, TICKETS ET TOURNÉES
Terrain est la carte centrale des tickets du périmètre actif. Les filtres
Équipes et groupes, Techniciens, type et statuts choisissent ce périmètre.
Explorer les sites conserve aussi les sites à zéro ticket, avec les stocks,
préconisations et la copie des IDs. Pour voir toutes les références,
ouvrir Gérer le référentiel → Carte des sites.
Sélectionner des tickets ou un lieu permet de Préparer une tournée.
Vérifier son aperçu avant Créer le brouillon ; enregistrer ensuite la tournée.
Les affectations sont observées dans les tickets ; les visites PRÉVUES
correspondent au planning enregistré, jamais à une position GPS actuelle.

CARTES INTÉGRÉES
Les cartes s’affichent dans la fenêtre principale, sans compte ni clé API.
Elles utilisent les coordonnées enregistrées dans le référentiel.
À leur ouverture explicite, les rues OpenStreetMap sont demandées par défaut,
en usage normal comme en simulation. Leur affichage nécessite Internet.
Si les tuiles sont indisponibles, le fond local conserve les repères.
Fond hors ligne choisit volontairement ce fond ; Afficher les rues réessaie.
Les demandes de tuiles n’envoient ni titres de tickets, ni noms de techniciens,
ni texte d’adresse. Aucun géocodage automatique n’est effectué.

Une commune seule est un repère approximatif ; un site sans coordonnées
ne reçoit pas silencieusement le centre de sa commune. Les inconnus et les
ambiguïtés restent consultables dans les listes et les compteurs.
Les pointillés montrent l’ordre des visites à vol d’oiseau, pas un trajet
routier. Une étape sans coordonnées reste listée et interrompt la liaison.
