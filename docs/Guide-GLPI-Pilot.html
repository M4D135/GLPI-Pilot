Guide de prise en main · Version 3.10.2

GLPI Pilot

Une interface commune pour traiter les tickets, planifier les interventions et suivre l’activité, depuis GLPI ou une source CSV / Excel. Le partage entre postes reste facultatif.

1. Installer le pack et reprendre ses réglages

Choisir PROD pour le runtime WebView2 embarqué ou PROD-LIGHT pour utiliser le runtime Evergreen installé sur le poste. Les sources et tests se téléchargent séparément depuis le tag GitHub. Extraire tout le ZIP : sa racine contient GLPI-Pilot.exe, GLPI-Pilot-Admin.exe et wad. Ouvrir le lanceur Standard GLPI-Pilot.exe en conservant wad à côté. .NET, le runtime fixe WebView2 (dans PROD) et le pilote Playwright sont inclus. L’interface fonctionne localement ; Edge ou Chrome doit être installé et autorisé pour la collecte GLPI et son SSO.

Pour une mise à jour, fermer l’ancienne application et extraire le nouveau pack dans un nouveau dossier. Les préférences restent dans les données locales du compte Windows. Une sauvegarde précède la première ouverture d’une nouvelle version. Un deuxième lancement rappelle la fenêtre déjà ouverte.

Si les fichiers téléchargés sont bloqués, wad\support\DEBLOQUER_TOUT.cmd débloque le dossier complet de cette application et ses sous-dossiers.

2. Se repérer dans l’interface commune

La version 3.5 organise le travail dans quatre espaces : Accueil, Tickets, Interventions et Pilotage. Données et Réglages restent regroupés en bas du menu. Toutes les fonctions sont accessibles dans la même interface ; aucun choix de rôle « technicien » ou « chef d’équipe » n’est nécessaire. L’identité choisie sert aux filtres personnels et ne crée pas de compte.

EspaceÀ utiliser pour…
AccueilRetrouver les priorités, alertes et rendez-vous, reprendre un dossier ou démarrer une collecte.
TicketsRechercher dans la liste, lire la fiche à côté, travailler ses notes et actions, puis planifier les demandes et incidents.
InterventionsRéunir le planning commun, les ressources, la carte, les tickets à planifier et les tournées.
PilotageLire la météo, les volumes, les équipes, catégories et participants ; examiner les tickets anciens ; personnaliser et exporter la vue.
DonnéesConnecter et collecter GLPI, importer un extrait si nécessaire, vérifier la qualité et les correspondances, conserver les fiches et travailler avec l’équipe.
RéglagesAdapter la présentation, la météo, les connexions, la conservation et les automatismes ; choisir les fonctions facultatives et entretenir l’installation.

Pour commencer depuis GLPI : ouvrir Données → GLPI en direct, renseigner l’adresse de la recherche puis cliquer Lancer la collecte. Consulter ensuite Pilotage. L’import CSV / Excel reste disponible dans Autres façons de travailler. Depuis une mesure, ouvrir les lignes qui la composent ; depuis Interventions → À planifier, organiser les tickets de ces mêmes données.

Le bouton Choisir mon identité, dans le bandeau supérieur et sur l’Accueil, personnalise les filtres Mes tickets et Mes interventions. Rechercher son nom, puis cliquer C’est moi ; le choix reste mémorisé et modifiable depuis le même bouton. Voir le parcours d’identité pour ajouter un nom absent.

Les paramètres des équipes, catégories et seuils se trouvent dans Réglages → Seuils, équipes et règles météo. Les sites se gèrent dans Réglages → Sites et communes, également accessibles depuis la carte des tickets. Les compositions personnelles restent accessibles dans le sélecteur de Pilotage.

Assistant de langage, Lectures ciblées et Effectifs des sites sont masqués par défaut. Les activer dans Réglages → Fonctions facultatives fait apparaître leur commande dans l’espace concerné. Les effectifs servent aux ratios par personne ou poste d’un site ; ils ne représentent pas les techniciens affectés aux tickets.

Les modèles publics sont génériques. Pour reprendre vos intitulés, seuils, équipes et sites, utiliser votre propre classeur lors de l’import de données ou la commande Reprendre les paramètres d’un classeur Excel dans les règles du pilotage. Les chiffres sont recalculés depuis les incidents chargés ; les valeurs enregistrées dans les anciens graphiques Excel ne sont pas réutilisées comme résultats courants.

3. Connecter GLPI et extraire sa recherche

  1. Dans Données → GLPI en direct, coller l’adresse complète de la recherche GLPI, avec ses critères. Choisir Edge ou Chrome et le dossier des exports dans les réglages.
  2. Cliquer sur Lancer la collecte. Le navigateur réservé à la collecte reste réduit. Si une validation SSO visible demande une intervention, sa fenêtre s’affiche temporairement ; la collecte reprend discrètement après la connexion.
  3. Si une intervention est nécessaire, ouvrir Inspection et reprise → Afficher le navigateur, effectuer l’étape demandée puis revenir dans GLPI Pilot. Le logiciel ne renseigne pas les identifiants.
  4. Lire le bilan : lignes récupérées, méthode employée, totalité vérifiée ou limites à examiner. Consulter ensuite le relevé et ses commandes d’export.

Le navigateur utilise un profil dédié. Si le portail ouvre seulement l’accueil, utiliser les outils manuels pour préparer la recherche puis reprendre l’adresse de la page du navigateur. Les filtres stockés uniquement dans la session GLPI dépendent de cette session ; les repères peuvent demander un premier réglage sur une interface personnalisée.

Méthodes et contrôle du résultat

L’export CSV toutes les pages est prioritaire. Si cette commande est indisponible, le logiciel peut utiliser une option d’affichage complet existante puis, si autorisé, parcourir la pagination depuis la première page. La recherche, les totaux, les colonnes et un échantillon d’identifiants sont contrôlés.

Un transfert corrompu ou ambigu interrompt la collecte. Il ne déclenche pas un changement silencieux de méthode. Le fichier reçu reste intact. Un relevé partiel porte son état et ses avertissements ; une annulation n’est pas annoncée comme une réussite.

À vérifier ne signifie pas que les lignes sont inutilisables. Lorsque le CSV est valide et que les identifiants de l’échantillon concordent, des différences avec l’affichage GLPI n’empêchent pas de consulter le relevé, de produire le classeur Excel ou d’utiliser Pilotage et Interventions. L’état reste À vérifier et les avertissements précisent les limites. Un identifiant attendu absent au premier contrôle ou un CSV corrompu reste un motif de refus.

Le bilan sépare la réception des lignes, l’identité de l’échantillon et la concordance de ses valeurs. Toutes les lignes peuvent être reçues au total annoncé alors que des valeurs restent à vérifier. Une réception complète ne prouve pas que toute la recherche ou toutes ses valeurs concordent. Une ancienne archive sans ces observations ne reçoit pas de nouveaux constats à partir de ses avertissements.

Les widgets indisponibles peuvent être masqués en lecture et retrouvés dans Pilotage → Personnaliser la vue → Cartes et sections visibles. Source et fiabilité du calcul détaille les observations du relevé. Dans Données → Qualité et couverture, les collectes récentes proposent aussi un diagnostic local des cellules divergentes, consultable et exportable en JSON. Ce fichier contient les valeurs comparées et leurs codes Unicode ; il est distinct du journal général.

Le contrôle final de la recherche, du total et de l’échantillon reste actif. Le classeur automatique d’un résultat à vérifier porte a-verifier dans son nom ; le CSV natif conserve son nom et son contenu. Les textes complets des popups GLPI sont récupérés seulement si leur association au texte visible est vérifiée. Les signes inhabituels ne sont pas recodés automatiquement.

La limite de lignes règle le volume chargé dans l’application, sans tronquer le CSV natif reçu. Un total absent ou invérifiable empêche de confirmer l’exhaustivité. Une recherche peut évoluer pendant la récupération : utiliser un tri stable, et conserver les mêmes critères jusqu’à la fin.

4. Choisir une source CSV / Excel ou la démonstration

  1. Dans Données → Autres façons de travailler, cliquer Importer CSV / Excel. Les lignes du fichier deviennent la source active de l’espace habituel ; elles ne sont pas des données d’essai.
  2. Pour Excel, vérifier la feuille visible et sa ligne d’en-têtes. Le profil Paramétrage, lorsqu’il est reconnu, permet de reprendre météo, équipes et sites pour cette source, sans modifier les réglages globaux.
  3. Consulter les listes et indicateurs, filtrer, exporter, préparer le calendrier ou les tournées. Ouvrir une ligne affiche uniquement les champs du fichier.
  4. Les suivis, tâches, solutions, pièces jointes et actions sur GLPI nécessitent une collecte par navigateur. Ces fonctions sont bloquées en source fichier, avec une explication.
  5. Dans Données, choisir Revenir à la source précédente ou Fermer cette source. Les interventions créées restent dans le planning habituel. La récolte automatique reprend selon les réglages après la fermeture du fichier.

Source CSV / Excel identifie les données importées. Un fichier entièrement lu ne certifie pas la couverture du portail GLPI. Une formule sans résultat enregistré ou une lecture limitée reste signalée.

Formats acceptés : CSV, TSV, TXT, XLSX et XLSM. Les valeurs enregistrées sont lues sans exécuter formule, macro ni liaison externe. Convertir un ancien XLS en XLSX ou CSV. Annuler la sélection ou rencontrer un fichier modifié conserve la source précédente. Les sauvegardes explicitement lancées se terminent avant de changer de contexte.

Une démo immédiatement utilisable

Ouvrir la démonstration charge une base fictive isolée : 60 tickets avec descriptions, suivis et tâches, des solutions pour les tickets terminés, six techniciens et quatre sites. Le calendrier contient six interventions dont deux effectuées et une récurrence hebdomadaire, ainsi qu’une formation. Quatre tournées sont présentes : deux effectuées, une prête et une à préparer. Huit dossiers ont déjà notes et checklists, certains avec rappels et épingles.

Essayer les actions, la collecte, le partage et les mises à jour utilise des adaptateurs locaux. Quitter la simulation restaure les données et réglages habituels. Importer un fichier depuis la démo active une source réelle. Les exports explicitement enregistrés sont conservés à l’emplacement choisi.

5. Rechercher, filtrer et exporter la liste des tickets

Dans Tickets, la recherche et les filtres portent sur toutes les lignes chargées, avant l’affichage paginé de 50 à 500 lignes. La recherche inclut les colonnes masquées. Un clic sur un en-tête trie le résultat ; Maj + clic ajoute un niveau de tri.

Filtres et tri réunit les conditions de colonnes et jusqu’à quatre niveaux de tri. Dans Outils du tableau, Choisir les colonnes règle visibilité, ordre et largeur ; Vues mémorisées conserve recherche, filtres, tri et présentation. Une vue reste liée à la structure exacte des en-têtes pour ne pas appliquer un filtre à une autre colonne.

L’export complet conserve toutes les lignes et colonnes du relevé. Exporter la vue utilise les critères courants et les colonnes visibles, y compris les lignes correspondantes au-delà de l’aperçu.

Importer un fichier ouvre un espace complet à partir d’un fichier CSV, TSV, TXT, XLSX ou XLSM. L’aperçu Excel permet de choisir feuille et en-têtes et, lorsqu’il existe, de reprendre le profil Paramétrage. Voir Source fichier et démonstration pour les fonctions disponibles et le changement de source.

Dans une simulation, les mêmes recherches, filtres, exports et fiches restent disponibles. Une valeur manquante ou non interprétable reste explicitement indisponible. Le tableau conserve les dix-neuf champs d’un extrait métier, leurs valeurs brutes et leurs correspondances.

6. Lire une fiche et conserver son travail

Dans Tickets, ouvrir une ligne affiche sa fiche dans le même espace. Sur une fenêtre large, la liste et le lecteur se présentent côte à côte. Sur une fenêtre plus étroite, Retour à la liste retrouve la recherche, les filtres, le tri, la sélection et le défilement tant que le relevé est inchangé. Ticket précédent et Ticket suivant suivent la séquence de la liste.

La fiche rapproche les faits source, l’attribution, les observations datées et les événements recueillis. Actualiser la fiche relit les contenus disponibles ; Afficher dans GLPI reste une action explicite. En simulation, ces actions utilisent la fiche simulée. Les différences entre deux lectures sont des changements observés, pas une reconstruction de tous les événements du portail.

Notes et rappels donne accès au travail personnel. Utiliser Enregistrer mon travail pour conserver notes, checklist et rappels sur le poste, ou Enregistrer et partager la note pour leur publication explicite. Les notes non enregistrées restent identifiées comme brouillon personnel.

Brouillon de suivi ouvre le texte préparatoire. Ses écritures en attente sont terminées dans le contexte courant avant de fermer le lecteur ou de changer de simulation. Actions assistées permet de préparer une modification, d’examiner son aperçu, puis de confirmer l’envoi ou l’application simulée. Un état incertain reste à vérifier.

Planifier prépare une intervention liée au ticket. Interventions liées retrouve les réservations enregistrées et permet de rouvrir leur fiche ; un même ticket peut participer à plusieurs visites.

Autres outils ouvre la synthèse, la recherche dans les rubriques, la passation, les rapprochements et la planification. Les recherches de chronologie portent sur les événements effectivement recueillis. Les sections absentes ou partielles restent signalées.

Mes dossiers retrouve les dossiers conservés, y compris lorsque leur ticket n’est plus dans le relevé. Les solutions et rapprochements présentent leurs références. Chercher des solutions similaires ouvre les précédents disponibles ; fermer ce dialogue retrouve la fiche et sa saisie.

7. Personnaliser et explorer le pilotage

Dans Pilotage, le sélecteur de composition propose le pilotage du service et vos tableaux personnels. Les dispositions globales et personnelles restent indépendantes. Cliquer Personnaliser la vue pour ajouter, régler, ordonner, dupliquer, masquer ou verrouiller les widgets. Terminer la composition retrouve la lecture normale.

Dans Personnaliser la vue, utiliser Ajouter un widget ou Ajouter une section. Régler la section modifie son titre, sa description, sa couleur, sa position et sa visibilité. Cartes et sections visibles retrouve aussi les éléments masqués. Une section peut subsister vide. Nom et organisation règle la composition, sa densité et son rappel de fraîcheur.

Les commandes ↑ et ↓ ordonnent les cartes de la section. Dans Régler, choisir la section, la largeur sur douze colonnes, la hauteur ou la hauteur automatique, ainsi que le début d’une nouvelle ligne. Verrouiller l’ordre et les dimensions protège la disposition du widget. Annuler et Rétablir permettent de revenir sur une modification.

Filtres ouvre Périmètre commun à toutes les analyses. Les conditions de Périmètre A sont enregistrées dans la composition ; les équipes et le technicien choisis en haut s’y ajoutent. Chaque widget peut encore appliquer ses propres conditions. Réinitialiser retire les restrictions communes et la sélection courante, en conservant les filtres propres aux widgets.

Renseigner Nom du contexte à conserver puis appliquer mémorise les conditions communes dans un contexte nommé. Le sélecteur Contexte enregistré et les commandes Charger le contexte/Supprimer le contexte permettent de le reprendre ou de le retirer. Ces contextes conservent les conditions, indépendamment de la disposition et des sélections d’équipes ou de technicien. Le détail Comparer deux périmètres active A/B : B utilise la même source et l’éventuelle identité personnelle, avec ses conditions indépendantes de celles de A.

Cliquer Détail, un volume ou une catégorie ouvre les lignes contributrices dans un aperçu large. Les identifiants, dates, statuts et textes ont des colonnes adaptées ; les cellules sont alignées en haut et les textes longs sont limités à trois lignes. Un clic, ou Tab puis Entrée/Espace, ouvre la valeur brute complète et son interprétation. Pagination et exports conservent le périmètre complet.

Les filtres Catégorie et Catégorie active peuvent inclure les descendants : la catégorie choisie et ses branches séparées par > sont retenues. Un simple préfixe de mot ne crée pas de correspondance. Les valeurs d’un même filtre sont reliées par OU ; plusieurs filtres se combinent par ET et une exclusion retire l’union choisie.

Les visualisations comprennent indicateurs, anneaux, jauges, histogrammes, matrices, barres empilées, Pareto, quantiles, boîtes statistiques et nuage ancienneté/échéance. Les méthodes, champs disponibles et effectifs accompagnent les mesures. Un champ absent reste indisponible.

Les indices de « météo » décrivent la santé du relevé : échéances, qualité, localisation ou synthèse. Leurs poids et seuils se règlent dans les réglages du widget. Ils ne sont pas des prévisions climatiques. Les durées sont calendaires et ne prouvent pas à elles seules le respect d’un SLA GLPI.

La présentation Météo du stock s’applique à un indicateur de volume, avec deux seuils orange et rouge. Le changement de couleur exige un dépassement strict : avec un seuil orange de 30, 30 reste maîtrisé et 31 passe à surveiller. Les cartes natives sans règles personnalisées utilisent des seuils de départ : 100 / 200 pour le stock global, 50 / 100 pour incidents et demandes, 10 / 20 pour catégories et équipes. Ces repères sont à adapter dans Réglages → Seuils, équipes et règles météo. Les seuils importés ou déjà enregistrés sont conservés ; Remplir les seuils vides complète explicitement les cases absentes. Une carte volontairement sans seuils affiche Seuils à définir. Le nombre reste consultable lorsqu’un relevé doit être vérifié. Le modèle Météo et pilotage du service fournit un tableau prêt à adapter.

Le filtre Équipes affiche chaque périmètre une seule fois : une équipe qui reprend exactement un groupe GLPI n’ajoute pas un second choix. Les correspondances qui réunissent plusieurs groupes restent disponibles et en précisent le contenu. La recherche retrouve les noms des équipes et de leurs groupes.

Lorsqu’une équipe sélectionnée couvre exactement le périmètre de sa règle météo, la carte principale utilise ses seuils et sa carte détaillée n’est pas répétée. Les équipes hors sélection disparaissent de l’affichage courant. Pour plusieurs équipes ou un sous-ensemble sans seuil adapté, le volume reste affiché avec une évaluation neutre et une explication ; les seuils ne sont pas additionnés. Personnaliser la vue conserve les cartes temporairement écartées, et retirer le filtre retrouve la composition complète.

Le rappel de fraîcheur se règle dans les règles météo ou dans l’organisation de la composition. Le modèle de service utilise 48 heures ; laisser la valeur vide désactive le rappel. Un relevé plus ancien demande une actualisation sans changer ses volumes ni ses couleurs météo. Le rappel ne s’applique pas à une archive consultée.

Les matrices Groupes × statuts et Types × statuts décrivent les tickets actifs, y compris ceux en attente ou planifiés. Un ticket affecté à plusieurs groupes participe une fois à chaque groupe ; la somme des groupes peut donc dépasser le stock global. Dans un filtre Groupe ou ligne de tableau, saisir un nom par ligne réunit ces groupes par OU, sans doublonner le total du périmètre.

Les vues des plus anciens proposent cinq tickets par groupe ou les dix plus anciens du périmètre courant. La seconde ne répète pas une même ligne multigroupe. Le classement utilise l’ouverture, puis l’identifiant numérique ; les égalités gardent l’ordre source. Les dates absentes, illisibles ou futures restent comptées dans le stock, sont signalées séparément et n’entrent pas dans le classement. Une ouverture du même jour a un âge de zéro. Les couleurs comparent les âges du périmètre, sans seuil SLA ; deux lignes portant le même identifiant ne sont pas fusionnées silencieusement.

Participation des rédacteurs · suivis et tâches affiche, pour chaque personne, les tickets avec suivi, avec tâche, avec les deux et leur union. L’union vaut suivis + tâches − intersection. Rédaction et attribution par personne compare cette union aux tickets attribués au technicien. Ces colonnes peuvent se chevaucher : les additionner ne donne pas un stock distinct et ne mesure pas la productivité.

La liste des participants est dynamique. Dans les réglages du widget, Liste facultative des participants et alias permet de définir des regroupements explicites. Des identifiants différents ne sont pas fusionnés sur la seule ressemblance du nom ; une correspondance ambiguë reste dans Autres. Non renseigné distingue l’absence de rédacteur de l’absence d’attribution. Un champ manquant rend sa mesure indisponible, sans produire un zéro artificiel.

Le menu Analyser et organiser propose Nouvelle composition, Importer une composition et Exporter la composition. L’import présente son aperçu, les renommages et la capacité disponible ; choisir explicitement l’ajout ou le remplacement avant application. L’ajout conserve les compositions et contextes existants.

Exporter propose un rapport HTML complet, un bilan CSV/Excel, un PDF ou une image PNG de la zone visible. Les courbes et mini-historiques utilisent les archives comparables : identité personnelle, filtres communs et filtres du widget sont rejoués à la date de chaque archive. Une archive incompatible, un filtre indisponible, une mesure absente ou une limite de calcul créent une rupture explicite. Activer Mini-historique sur l’indicateur et choisir sa fenêtre dans Régler.

Pour les cartes météo d’équipe, un ticket revient à la première équipe correspondante dans l’ordre configuré ; une carte masquée continue de participer à cet ordre. La visibilité et l’activation de la couleur sont distinctes : un volume peut rester affiché sans météo active.

8. Construire des analyses et requêtes

Ouvrir Pilotage → Analyser et organiser → Construire une analyse. L’atelier contient 80 modèles. Modèles + ajoute les définitions absentes au brouillon sans remplacer les requêtes existantes ; enregistrer pour conserver les changements. Jusqu’à 128 définitions peuvent être mémorisées.

Assembler des groupes imbriqués ET / OU / NON, comparer des champs compatibles, utiliser des listes, intervalles et paramètres typés. Les champs calculés utilisent un catalogue borné, sans script ni SQL arbitraire.

Regrouper jusqu’à trois niveaux et calculer comptes, sommes, moyennes, médianes ou percentiles. Consulter l’explication par ticket pour comprendre les conditions vraies, fausses ou indéterminées. Les résultats disponibles peuvent alimenter les widgets.

9. Choisir son identité et organiser les capacités

  1. Cliquer Choisir mon identité dans le bandeau supérieur ou sur la carte de l’Accueil. Le panneau Mon identité s’ouvre depuis l’écran courant.
  2. Rechercher son nom ou son identifiant, puis cliquer C’est moi sur la bonne personne. Les propositions viennent des tickets chargés et des participants du planning ; aucune interrogation d’un annuaire n’est lancée.
  3. Si le nom manque, cliquer Mon nom n’est pas dans la liste, renseigner Nom tel qu’il apparaît dans les tickets, puis Enregistrer mon identité. Ce parcours fonctionne aussi sans relevé chargé.

Le nom choisi apparaît dans le bandeau et reste mémorisé dans le profil local. Cliquer ce bouton pour changer d’identité ou choisir Retirer mon identité. L’écran courant et la date du planning restent en place ; les interventions et les participants enregistrés sont conservés. En simulation, le choix reste dans l’espace de test.

Mes tickets propose ce choix lorsqu’il manque, puis applique le filtre personnel. Mes interventions utilise la même identité. Les clés existantes sont conservées ; une saisie différente uniquement par la casse ou les espaces reprend une correspondance unique. Plusieurs correspondances demandent un choix explicite et les anciens participants manuels ne sont pas fusionnés automatiquement.

Cette sélection ne crée ni compte, ni mot de passe, ni rôle, et ne constitue pas une connexion GLPI ou Windows. Toutes les fonctions restent accessibles. Les volumes, urgences, attentes et échéances décrivent le relevé observé ; ils ne mesurent pas une productivité individuelle.

Les outils Pilotage → Analyser et organiser → Charge des techniciens et Capacités et planning restent disponibles pour déclarer compétences, secteurs, remplaçants, absences, capacités et estimations de durée, puis comparer les répartitions possibles et leurs charges avant/après. Une proposition locale ne modifie pas les affectations GLPI.

Accueil rassemble les priorités et rappels. Les notes, checklists et reports se travaillent dans Tickets. Les interventions datées se préparent dans Interventions → Planning. Vérifier les données observées et les disponibilités déclarées avant d’organiser une visite.

10. Planifier les interventions dans le calendrier commun

Interventions réunit trois onglets : Planning, Carte et Tournées. Dans Planning, choisir Jour, Semaine, Équipe · semaine, Mois ou Agenda. La date, la présentation, les filtres et la position de lecture sont mémorisés pour votre contexte local.

  1. Cliquer Nouvelle intervention ou un créneau. Depuis une fiche, utiliser Planifier. Depuis À planifier, cocher plusieurs tickets puis Planifier la sélection.
  2. Renseigner l’objet, la nature, le début, la fin et le fuseau. Une intervention libre fonctionne avant toute collecte, avec aucun ticket ou plusieurs tickets, et avec zéro, un ou plusieurs participants.
  3. Choisir le site ou saisir le lieu et l’adresse ; activer À distance si nécessaire. Ajouter contact, matériel, consignes, compétences requises, marges de trajet et rappel selon le besoin.
  4. Examiner les contraintes puis enregistrer. Les chevauchements, absences, capacités et autres contraintes connues sont explicités. Maintenir un conflit demande une action volontaire ; un horaire impossible au changement d’heure doit être corrigé.

Le panneau reste à côté du calendrier. Déplacer ou étirer un rendez-vous modifie son horaire après contrôle ; un conflit ouvre la proposition à examiner. Les mêmes horaires sont modifiables dans le formulaire au clavier. Une saisie non enregistrée reste protégée quand vous changez de vue.

Planning commun affiche le périmètre choisi ; Mes interventions utilise votre identité. La commande Filtrer permet de cumuler des équipes et des techniciens. Le bouton d’identité du bandeau ouvre Mon identité sans quitter le calendrier ni changer sa date. Options → Techniciens et disponibilités reste disponible pour ajouter un participant et déclarer ses plages hebdomadaires et capacités particulières, même sans fichier d’incidents.

Les récurrences peuvent être quotidiennes, hebdomadaires ou mensuelles. À la modification, choisir Cette occurrence, Cette occurrence et les suivantes ou Toute la série. Les exceptions permettent d’exclure une date ou de remplacer son horaire. Options → Déplacer plusieurs interventions prépare un décalage commun, affiche son aperçu et applique le lot après confirmation. Annuler cette modification restaure la dernière action lorsque ses versions n’ont pas changé depuis.

Une intervention avec deux participants est comptée une fois. Tickets liés dénombre les références distinctes ; Heures-technicien multiplie la durée par les participants : 90 minutes avec deux techniciens représentent 3 heures. Les disponibilités inconnues restent inconnues. Ces données décrivent des réservations déclarées et ne mesurent pas la présence réelle.

La carte du planning suit la période et les filtres. Un repère ouvre l’intervention ; les lieux sans coordonnées et les interventions à distance restent dans une liste visible. Les visites des tournées enregistrées apparaissent dans le calendrier et se modifient dans leur onglet Tournées. La carte représente des lieux prévus, sans suivi des personnes en temps réel.

Dans Options, retrouver les rappels, exporter le calendrier ICS, exporter les fiches d’intervention imprimables ou imprimer le planning. Les rappels de l’identité sélectionnée se déclenchent automatiquement tant que l’application reste ouverte, hors plages silencieuses, verrouillage et édition. Ils ne fonctionnent pas après sa fermeture ; la simulation n’envoie aucune notification système réelle. Aucun courriel ni invitation externe n’est envoyé. Les états du planning ne modifient pas automatiquement les tickets GLPI.

Avec le partage, Versions à examiner compare un lot concurrent en entier, y compris une suite de série qui n’a pas été acceptée. Exporter les versions, conserver l’actuelle ou appliquer la proposition après examen. La fenêtre de lecture est limitée à 93 jours et les déplacements groupés acceptent 50 sélections. Le contrôle d’une série part d’une période de 366 jours, étendue si des exceptions le demandent ; la période examinée est annoncée et un lot couvrant plus de deux ans est refusé. Voir Calendrier et interventions pour les règles de fuseau, de récurrence, d’annulation et de partage.

11. Explorer le terrain et gérer les lieux

Réglages → Sites et communes permet plusieurs termes pour une ville : VE ; Ville-Exemple = Ville Exemple. La détection prend en compte mots entiers, accents et noms composés. Une ambiguïté reste visible au lieu d’attribuer arbitrairement une ville.

Définir régions, départements, secteurs, sites, adresses et coordonnées facultatives. Régler l’ordre des sources, conditions et exclusions, puis simuler les changements pour examiner les tickets affectés et les preuves de détection.

Un site sans commune renseignée peut être créé, importé, reconnu par ses alias et utilisé dans un panier de tournée. Son rattachement peut être complété plus tard sans perdre son identité. Aucun nom de ville ni point sur une carte n’est déduit arbitrairement. Un CSV minimal Type;Nom;Alias avec le type Site suffit pour ces lieux.

Dans Réglages → Sites et communes, choisir le type Site affiche la colonne Termes de détection : elle contient le nom du site et ses alias. Le nom est reconnu automatiquement ; le champ Alias et variantes permet d’ajouter d’autres termes. Après la reprise d’un profil de classeur, un brouillon non modifié se remet à jour avec le référentiel enregistré. Les modifications d’un brouillon en cours sont conservées ; un conflit demande de le recharger avant de poursuivre.

Préparer les sites d’une distribution

  1. Préparer un CSV UTF-8 dont les colonnes obligatoires sont Site;Termes de détection. Ajouter si besoin Ville;Code postal;Adresse;Latitude ville;Longitude ville;Latitude site;Longitude site. Un tableau Excel peut être enregistré en CSV. Le nom du site est reconnu automatiquement.
  2. Placer ce fichier sous le nom exact sites.csv dans le dossier wad du pack destiné aux utilisateurs.
  3. Lancer GLPI-Pilot.exe. Lors de la première initialisation réussie de ce profil, l’application reprend discrètement les sites dans %LOCALAPPDATA%\GLPI-Pilot\settings.json. Ils sont consultables dans Réglages → Sites et communes → Type : Site et modifiables normalement.

La première initialisation ajoute les références. Dans un profil déjà initialisé, une nouvelle version géographique du fichier complète uniquement les champs vides des sites et communes toujours présents. Elle conserve leurs identifiants et les valeurs saisies, ne recrée pas les sites supprimés ou renommés et ne réintroduit pas les alias retirés. Une sauvegarde précède l’enregistrement. Un fichier identique ne provoque aucune réécriture. Si wad/sites.csv est absent, le démarrage se poursuit normalement.

Les coordonnées de commune servent aux regroupements de villes, celles du site à localiser le lieu. Une commune peut avoir plusieurs codes postaux ; les renseigner dans son champ Code postal et conserver le code de l’adresse physique du site dans son adresse. Le logiciel et le pack public sont génériques. Le fichier de sites reste local à votre organisation et ne fait pas partie du dépôt ni des nouvelles releases GitHub. Le bouton Importer un CSV… du référentiel conserve son format structuré Type;Nom;Alias et son aperçu. Pour le fichier de démarrage, utiliser le placement dans wad décrit ici et les notes de version.

Carte des tickets → Explorer les sites conserve tous les sites du référentiel, y compris ceux à zéro, et indique le volume sans site précis. Les stocks et préconisations suivent les filtres de la carte. Copier les IDs copie tous les identifiants renseignés du site, avec leurs occurrences répétées. Voir sur la carte sélectionne ce lieu ; Modifier le site ouvre sa référence. Le widget de stock des sites reste aussi disponible dans une composition de Pilotage, avec ses lignes contributrices.

Lire la couverture des sites dans le bon périmètre

Dans la Carte des tickets, ouvrir Équipes et groupes, cocher les choix puis Appliquer. Les choix sont reliés par OU : une même ligne correspondant à plusieurs choix reste comptée une fois. Toutes retire cette restriction. Le filtre Techniciens accepte aussi plusieurs personnes ou les tickets sans attribution. Type et statuts actifs complètent le périmètre. Mes tickets utilise votre identité personnelle ; si elle manque, choisir son nom dans le panneau proposé applique ensuite ce filtre.

La recherche du dialogue facilite le choix dans une longue liste ; jusqu’à 64 équipes/groupes et 64 techniciens peuvent être retenus. Le stock, les repères, la liste détaillée, les IDs copiés et les préconisations suivent le même périmètre. Un lien depuis Pilotage reprend les équipes et le technicien transmis. Un choix disparu demande une actualisation explicite. Modifier le périmètre renouvelle la carte et remet sa sélection de tickets à zéro.

Certaines équipes renseignent un site dans le titre et d’autres non : un périmètre global donne donc une couverture différente d’un focus de service. Les cartes des tickets distinguent le stock, les tickets avec coordonnées, les localisations approximatives par commune et les lignes sans coordonnées. Sur la carte compte des tickets placés, pas le nombre de lieux distincts.

Dans les indicateurs de localisation de Pilotage, Localisation reconnue comprend une commune unique ou un site unique, même sans commune ni coordonnées. Localisation à vérifier comprend les lieux inconnus, titres absents et ambiguïtés, y compris plusieurs sites dans une même commune. Lorsque le repérage est disponible, ces deux compteurs se partagent le stock actif. Une localisation reconnue peut donc rester absente de la carte faute de coordonnées.

Le tableau de planification exige un site précis. Une commune reconnue seule contribue à la localisation reconnue, mais reste dans la ligne des sites non renseignés ou à vérifier. Les correspondances dans les titres conservent leurs règles : mots entiers, accents et ponctuation normalisés, noms et variantes du référentiel. Le logiciel conserve explicitement les cas ambigus.

Les préconisations sont Aucun ticket à zéro, À suivre pour un site connu sous le seuil et Intervention à planifier à partir de quatre tickets par défaut. Les tickets sans site précis demandent une vérification. Le repère d’intervention se règle dans le profil de pilotage, ou dans le widget concerné pour une composition personnalisée. Cette indication ne réserve aucune visite.

Corriger le site, dans chaque ligne du tableau de la carte, permet de choisir un site enregistré par son nom ou un alias. La commune suit automatiquement le site. Les cases du tableau permettent d’appliquer le même site à plusieurs tickets, avec un motif proposé et modifiable. La correction apparaît immédiatement et peut être retirée. Corriger une localisation ouvre la file de vérification détaillée. Les corrections restent liées à la source et à l’identifiant unique du ticket.

Ces corrections sont aussi disponibles dans le dernier relevé du cache local, sans le fichier d’origine, et reviennent au redémarrage. Les cellules importées et les archives sont conservées. Actualiser recharge l’affichage ; pour appliquer de nouveaux alias à l’ensemble des tickets, enregistrer le référentiel puis réimporter le CSV/Excel des tickets ou lancer une nouvelle collecte. Un centre de commune ne représente jamais l’adresse précise d’un site.

Dans Interventions, le bouton Actualiser du bandeau recharge la vue affichée avec son onglet, sa date et ses filtres. Il ne rouvre pas le référentiel après sa fermeture. Sur la carte, la recherche, le lieu choisi, le cadrage et la sélection restent conservés lorsque le relevé et le périmètre sont toujours compatibles. Une saisie d’intervention reste ouverte ; une saisie de tournée non appliquée demande une confirmation avant rechargement.

Consulter la carte intégrée

Depuis Interventions → Carte, choisir Explorer les tickets sur la carte pour ouvrir la carte des tickets. La commande Carte des tickets de l’Accueil rejoint directement cette même vue. Sélectionner un regroupement dans la liste ou son repère affiche ses tickets détaillés. Les tickets inconnus, ambigus ou sans coordonnées restent consultables. Ouvrir rejoint la fiche ; les cases permettent de préparer une sélection pour une tournée. La commande Carte des sites du référentiel affiche également tous les lieux enregistrés, même sans ticket.

Les repères et la liste sont liés : choisir un lieu dans la liste centre la carte ; choisir un repère retrouve sa ligne. Utiliser le zoom ou Tout afficher pour retrouver l’ensemble des lieux. Un lieu sans coordonnées reste clairement signalé. Son adresse ou le centre de sa commune ne sont pas transformés en position précise de site.

Les rues OpenStreetMap se chargent à l’ouverture explicite de la carte, en usage normal comme en simulation. Si le fond est indisponible, Natural Earth prend le relais en conservant les repères. Fond hors ligne le choisit volontairement ; Afficher les rues permet de réessayer. Le fond local représente les terres à petite échelle, sans rues. Les demandes de tuiles ne contiennent ni titres de tickets, ni noms de techniciens, ni texte d’adresse.

Les affectations affichées sont celles des tickets observés. La couche Visites PRÉVUES utilise la date choisie et les tournées enregistrées. Elle ne représente pas la position actuelle des techniciens. Un repère de commune porte son caractère approximatif ; un site sans coordonnées ne reprend pas silencieusement le centre de cette commune.

Pour les ratios, activer Réglages → Fonctions facultatives → Effectifs des sites, puis ouvrir Carte des tickets → Options du terrain → Effectifs des sites · facultatif. Choisir personnes ou postes, valeur, référence et période de validité. Le stock et la détection restent utilisables sans effectif ; une période absente laisse le ratio indisponible.

12. Préparer et suivre les tournées

Dans la Carte des tickets, sélectionner des tickets de la liste ou Sélectionner les tickets de ce lieu, puis cliquer Préparer une tournée. Choisir nom, date et technicien prévu ; examiner les étapes et les tickets non localisés avant Créer le brouillon. Jusqu’à 2 000 tickets peuvent être retenus ; un dépassement est refusé sans tronquer la sélection. Un brouillon existant non enregistré est protégé.

Après une nouvelle extraction, rapprocher la tournée du relevé : tickets absents, réaffectés ou résolus demandent un examen. La reconstruction des étapes reste une action explicite. Retirer une tournée du registre la conserve comme brouillon affiché jusqu’au changement de tournée ; elle ne se réenregistre que sur demande explicite.

Exporter une fiche HTML imprimable ou un calendrier ICS. Les trajets sont saisis ou indicatifs par défaut ; un service OSRM compatible peut fournir des distances et durées routières après configuration et consentement. Un service Open-Meteo peut fournir les prévisions des sites, avec source et date. Le calendrier produit est un fichier à importer, pas une invitation envoyée à un collègue.

Carte de la tournée conserve toutes les étapes numérotées, avec un parcours distinct par journée et affectation. Les pointillés montrent l’ordre des visites à vol d’oiseau ; ils ne constituent pas un tracé routier et ne changent pas les durées du planning. Une étape sans coordonnées reste dans la liste et interrompt la liaison. Carte · ordre des communes utilise explicitement les positions des communes, sans les présenter comme des adresses de sites. Le repli local reste utilisable sans Internet, dans les deux modes.

Le brouillon de tournée se retrouve dans Interventions → Tournées, ou dans le panneau de tournée ouvert depuis la carte des tickets. Organiser les arrêts, départ et retour, durées, fenêtres horaires, contacts, compétences et étapes verrouillées, puis Enregistrer la tournée. Fermer le panneau applique les champs valides de son en-tête au brouillon ; un champ invalide garde le panneau ouvert avec son erreur. L’enregistrement durable reste distinct.

Tournées prévues ouvre le registre et le calendrier ; Continuer le planning reprend le brouillon. Options du terrain donne accès au panier et à l’ordre des communes, ainsi qu’aux services de route et de météo. Les calculs routiers facultatifs ne sont pas déclenchés par le simple affichage du fond de rues.

13. Conserver les fiches, retrouver des solutions et partager

Dans Données, les commandes Chercher une fiche, Retrouver une solution, Échanges de l’équipe et Partage entre postes ouvrent les panneaux correspondants. Relevés partagés permet aussi de charger la liste de tickets recueillie sur un autre poste. Actualiser le cache lit l’index GLPI de tous les statuts accessibles, y compris résolus et clos, hors corbeille et dans les entités actives. Les onglets consultables, suivis, tâches, solutions et historiques sont conservés en SQLite sur le poste. Les fichiers binaires des pièces jointes ne sont pas téléchargés.

Dernière collecte → Détail de la collecte retrouve le bilan après redémarrage, avec compteurs, pagination et filtre sur les tickets à relire. Reprendre les tickets à relire réactualise l’index dans le même contexte avant de retenter les fiches encore accessibles. Une lecture partielle reste indiquée même lorsqu’une ancienne copie complète est conservée. Les nouveaux contenus attendent la confirmation finale de leur version ; une interruption conserve leur lecture sans les déclarer à jour.

Dans Données → Partage entre postes, choisir le dossier local du cache et renseigner le fuseau d’affichage des dates GLPI, par exemple Europe/Paris, ainsi que l’ordre jour/mois/année si GLPI affiche ses dates de cette façon. La mise à jour réutilise les détails complets seulement lorsque la date de modification, sa précision et l’âge du cache le permettent. Une date absente ou ambiguë entraîne une relecture. Relire tous les contenus force cette relecture. Le bilan indique les lectures partielles ou à reprendre ; une interruption conserve le travail déjà enregistré.

Le panneau Résolution recherche dans les tickets résolus ou clos dont les détails complets restent actuels selon les observations conservées. Les extraits citent leur ticket, leur section et leur date de lecture. Exporter le corpus RAG crée un JSONL avec les documents complets et leurs fragments de texte sourcés. Aucun modèle externe n’est contacté par cette recherche.

Dans une fiche conservée, rechercher ses précédents résolus retrouve jusqu’à huit tickets de la même installation, avec les termes et codes d’erreur communs ainsi que les extraits exacts. Le moteur utilise le titre conservé ; une recherche manuelle permet de préciser le symptôme. Une catégorie identique seule ne suffit pas, et les contenus partiels, périmés ou non confirmés sont exclus. Les solutions recueillies apparaissent en priorité. Consulter un précédent puis revenir garde la fiche de départ et le travail en cours. Les limites de la portion examinée restent visibles ; chaque proposition doit être vérifiée dans son contexte.

Le bouton Chercher des solutions similaires de l’écran Tickets ouvre directement ce parcours, en retrouvant la fiche avec son numéro et son adresse GLPI. Si elle n’est pas encore conservée dans la bibliothèque, un message l’indique ; la saisie et la fiche de travail restent ouvertes. Fermer le dialogue rend le focus au contrôle qui l’a ouvert. Revenir d’un précédent consulté retrouve la liste ou la fiche source avec la saisie conservée.

Le panneau Équipe réunit commentaires, connaissances, notes, propositions d’affectation et publications de configurations ou de statistiques. Les publications de configuration se prévisualisent avant reprise ; les versions concurrentes du registre commun disposent de leur propre comparateur. Publier dans cet espace n’écrit pas dans GLPI.

Depuis les notes d’un ticket, utiliser Enregistrer et partager la note. Les commandes de publication d’une tournée, d’une répartition ou de capacités restent disponibles pour une reprise ponctuelle. Lorsque le partage commun est activé, les données enregistrées de ces outils sont aussi synchronisées dans leur registre commun. Dans Données → Échanges de l’équipe → Examiner et reprendre, comparer la contribution avant de l’appliquer. Une note s’ajoute au texte personnel, une tournée devient un nouveau brouillon, et le scénario ou les capacités précédents sont sauvegardés avant remplacement. Favoris et notes personnelles des techniciens restent propres au poste.

Le partage facultatif utilise un dossier réseau commun ou un serveur PostgreSQL. Chaque poste conserve sa base locale et sa file d’attente. Le planning, les ressources et les données métier communes suivent ce mode de partage. Les notes personnelles se publient uniquement par leur action explicite. Voir le parcours de configuration du partage ci-dessous.

Dans l’espace d’équipe, Examiner les versions → Comparer tous les champs montre aussi les données structurées : horaires, affectations, capacités et réglages. L’aperçu distingue champ absent, valeur nulle et texte vide, avec filtre et limites explicites. Exporter les deux versions conserve les documents entiers en JSON. Une contribution enregistrée directement dans l’espace d’équipe est destinée au partage même en brouillon ; une note personnelle du lecteur ne l’est qu’après son action de partage.

Le cache SQLite actif reste sur un disque local, y compris en mode dossier réseau. Un changement vers un dossier local neuf copie la base et conserve l’ancienne. Le dossier partagé reçoit des fichiers d’échange versionnés. Le cache peut servir de relevé pour les outils locaux ; le lecteur ouvre alors les contenus déjà conservés et suspend sa lecture GLPI automatique. Voir Bibliothèque et partage pour le déploiement et le protocole.

14. Réunir les postes dans un espace partagé facultatif

Ouvrir Réglages → Partage entre postes ou Données → Partage entre postes. Choisir le mode voulu ; l’application reste complète en mode local.

ModeFonctionnement
Sur ce poste uniquementChoix initial. Les données, interventions et ressources restent locales.
Dossier réseau partagéChaque poste accède au même dossier Windows, avec les droits de lecture et d’écriture de sa session. Aucun compte GLPI Pilot supplémentaire n’est créé.
Serveur PostgreSQLUtilise un serveur commun et ses identifiants techniques. Le mot de passe peut rester limité à la session ou être protégé sur le poste.
  1. Préparer un dossier commun accessible depuis les postes de l’équipe, par exemple \\serveur\equipe\GLPI-Pilot. Utiliser un emplacement destiné aux membres qui doivent recevoir ces données.
  2. Choisir Dossier réseau partagé, puis Choisir le dossier partagé ou saisir son chemin. Conserver un dossier distinct et local dans Copie locale.
  3. Cliquer Tester la connexion. Le test vérifie l’accès et prépare au besoin le registre d’échange ; il n’active pas le partage tant que les réglages ne sont pas enregistrés.
  4. Choisir la synchronisation automatique et son intervalle, puis Enregistrer le partage. Cliquer Synchroniser pour le premier échange.
  5. Configurer le même dossier commun sur les autres postes. Vérifier les envois, réceptions, éléments en attente et l’heure de dernière réussite. La lettre du lecteur peut différer si elle désigne le même dossier réseau.

Le partage commun réunit la bibliothèque de tickets, le planning et ses ressources, les sites et règles, les tableaux de bord communs, les relevés conservés, les tournées, les capacités et compétences, les répartitions, les corrections de localisation et les ordres de tournée. Les identifiants GLPI, la session du navigateur, les mots de passe, l’identité de filtre, les favoris et les notes privées restent propres au poste.

Dans Données → Relevés partagés, vérifier la date, les lignes et les colonnes, puis Utiliser ce relevé. Les colonnes et valeurs sont conservées, y compris les champs de votre extrait. Les prochaines versions d’un même périmètre vérifié sont reçues lors des échanges ; une autre source ouverte volontairement reste en place. Une observation dont le périmètre n’a pas pu être vérifié garde sa propre identité. Deux recherches ou périmètres distincts ne sont pas fusionnés parce qu’ils utilisent le même portail. Un relevé dépassant 64 Mio avant compression ou 12 Mio compressés reste local avec une explication.

En cas de coupure, continuer sur la copie locale ; les changements restent en attente jusqu’au prochain échange. La synchronisation périodique demande que l’application soit ouverte et respecte les traitements et éditeurs en cours. Le dossier partagé contient le registre GLPI-Pilot-Shared ; le fichier SQLite actif de chaque poste reste local.

Les Données communes, dans les panneaux de partage ou d’équipe, présentent les versions concurrentes. Comparer et choisir expose les différences ; Exporter les versions complètes conserve l’ensemble des documents. Choisir la version actuelle ou la proposition reçue applique une décision vérifiée par sa révision. Les conflits du calendrier se traitent dans Interventions → Options → Versions à examiner, par lot entier.

La simulation reste isolée. Le test, les synchronisations, les contributions et les interventions utilisent ses données et ses répliques locales. Le chemin réseau ou le serveur réels ne sont pas contactés dans ce contexte. Voir Bibliothèque et partage pour les détails de déploiement, de reprise et de conservation.

15. Comparer les observations et examiner la qualité

Ouvrir Pilotage → Analyser et organiser → Comparer les observations. Chaque archive conserve provenance, critères observables, cellules et règles d’interprétation. Un contrôle d’intégrité est effectué à la lecture. Protéger les archives à conserver, régler la rétention et rouvrir un relevé pour l’exporter ou le consulter à sa date.

La rétention protège la dernière archive de chaque source et son dernier relevé complet comparable, ainsi que les archives épinglées. Ces protections peuvent faire dépasser le budget configuré. Une entrée de catalogue endommagée ne bloque pas les nouvelles sauvegardes.

Un ticket absent n’est pas un ticket résolu. La comparaison distingue apparitions, absences et modifications. Une résolution, réouverture ou réaffectation n’est comptée que si elle est observée entre deux lignes identifiables de relevés compatibles.

Dans Données → Qualité et couverture, examiner séparément l’exhaustivité, la disponibilité des champs et leur interprétation : valeurs vides, dates illisibles ou incohérentes, identifiants répétés et statuts non reconnus. Les contrôles donnent accès aux lignes à examiner.

Les analyses historiques proposent mouvements, cohortes, transferts, incertitudes, projections et taux fondés sur des effectifs datés. Les périodes incompatibles ou sans observation restent des lacunes explicites ; les filtres sont rejoués sur chaque archive.

16. Programmer les sources et suivre les alertes

Depuis Données → Mes recherches, mémoriser plusieurs recherches avec nom, URL, navigateur, méthode, repères, délais, dossier et formats propres à la source. Collecter plusieurs recherches ouvre une sélection explicite des recherches mémorisées. La collecte groupée les traite successivement et conserve le bilan de chacune, avec les réussites, les résultats à vérifier et les échecs. Le bilan propose un accès au relevé courant lorsqu’il reste disponible. Elle ne fusionne pas les tickets de plusieurs recherches. Une seule URL dans Configuration courante se collecte avec Lancer la collecte. Réglages → Collectes programmées ouvre la programmation. Elle est facultative et ne fonctionne que pendant que l’application reste ouverte.

Un traitement en cours, un éditeur intégré ouvert, une plage silencieuse ou le verrouillage de la session retardent le lancement. Le journal des opérations conserve les résultats et signale les travaux interrompus. La pagination peut reprendre un point conservé après contrôle de la première et dernière page, du total, des colonnes et du périmètre ; un point incompatible impose un nouveau départ.

Les alertes, consultables depuis Accueil et réglables depuis Réglages → Alertes, utilisent des indicateurs ou requêtes : seuil, échantillon minimal et exigence de complétude. Elles peuvent être prises en compte ou reportées. Une valeur inconnue, un relevé partiel ou un total incohérent ne résout pas une alerte exigeant un relevé complet. Les démonstrations, archives consultées et dashboards personnels ne déclenchent pas ces règles.

17. Régler l’interface et le mouvement

Le zoom va de 75 à 150 % et reste mémorisé sur le poste. Utiliser Ctrl +, Ctrl −, Ctrl 0, Ctrl + molette ou le champ de zoom dans Réglages → Confort et présentation. Le bouton de thème choisit clair ou sombre.

Dans ce même panneau, régler la densité, l’accent, le contraste renforcé, la perception des couleurs, le suivi du thème Windows et les colonnes figées. Choisir l’écran déplace la fenêtre sur un moniteur disponible. Les dimensions de fenêtre restent mémorisées.

Dans une carte météo de Pilotage, ouvrir Seuils pour cette sélection. Choisir une valeur absolue ou, pour un décompte de tickets compatible, Pourcentage (%). Diffusion réseau, patchs de sites et lanceurs

Le pack 3.10.1 fournit GLPI-Pilot.exe pour les agents et GLPI-Pilot-Admin.exe pour les responsables, avec le dossier wad commun. Retirez le lanceur Admin avant distribution aux agents : la mise à jour ne le remettra pas.

Dans Mise à jour et retour arrière, enregistrez un dossier partagé contenant le ZIP PROD et SHA256SUMS.txt, puis recherchez, copiez et vérifiez le pack avant de décider de l’installation. Un ZIP local reste possible ; l’application ne contacte aucun dépôt en ligne.

L’Admin peut exporter GLPI-Pilot-Sites-v1.csv et GLPI-Pilot-Sites.sha256 pour diffusion sur le même partage. Comparez les valeurs avant/après, puis confirmez le patch. Les identifiants et éléments absents sont conservés ; une sauvegarde précède les modifications. Un brouillon non enregistré doit être terminé avant le patch.

Les outils Admin de Partage entre postes permettent la remise à zéro SQLite avec sauvegarde et la préparation PostgreSQL avec identifiants temporaires. Le guide de diffusion et d’administration détaille les fichiers attendus, les droits et la restauration.
